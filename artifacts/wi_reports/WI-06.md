# WI-06 — 채택 게이트 3조건 (하드 게이트)

## STEP 1 SPEC
- 목적: C-15/C-16 해소 — 채택 게이트를 적합도 항이 아닌 하드 게이트로 구현.
  3조건: ① 전체 DETPass ② 핵심 부분집합별 DETPass ③ holdout ReplayFit, 각 −ε=1.0%p 허용.
- 변경 파일: `utils/ga_search/gate.py`(신규), `configs/ga_search_gate.json`(신규),
  `utils/ga_search/ga_engine.py`(최종 채택 시 게이트 적용), `utils/ga_search/cli.py`
  (`--gate-config`, `--gate-baseline`).

## 설계 결정
- C_crit(C-16): 레거시 category_group을 이식해 basic={1,2}, temporal={3,4,5}, complex={6,7,8}.
  논문의 '시간' 축은 temporal 그룹, '과거 실패' 축은 ③ holdout 리플레이 조건이 담당.
  **'안전' 축은 데이터셋에 안전 카테고리·검사가 부재해 구성 불가** — config `_doc`에 기록(FIX_PAPER 연동, 감사 C-01/C-16).
- 게이트는 탐색 중이 아니라 **최종 채택 시점**에 적용 — holdout이 탐색 신호로 새는 것을 방지
  (holdout 접근은 replay.py의 consumer="gate"/"report"로만 가능).
- baseline 부재(첫 채택) → 공허 통과 + baseline_missing 기록.
  candidate의 holdout ReplayFit이 없는데 baseline에 있으면 → 회귀 검증 불가로 거절(보수적).
- ε 경계(정확히 −1.0%p)는 허용(부동소수 1e-9 여유).
