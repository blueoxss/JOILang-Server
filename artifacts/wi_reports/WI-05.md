# WI-05 — 리플레이 search/holdout 분리 + ReplayFit 구현

## STEP 1 SPEC
- 목적: C-05/C-14 해소 — 저장소에 부재하던 ReplayFit(리플레이 재해결율) 계산을 신규 구현하고,
  탐색용(search)/보류용(holdout)을 분리해 적합도는 search만, 보고(·향후 게이트)는 holdout만 보게 한다.
- 변경 파일: `utils/ga_search/replay.py`(신규), `tools/build_replay_split.py`(신규),
  `utils/ga_search/ga_engine.py`(배선), `utils/ga_search/cli.py`(`--replay-split`),
  산출물 `datasets/replay_split.json`.

## 실측 기반 설계 결정 (P-4 ① 데이터 사실 우선)
- 리플레이 원천: `datasets/usr_rag/*.csv` 26파일 33행 → **고유 사례 30건** (중복 3 제거).
  best_code는 Python 리터럴 → `ast.literal_eval`로 정규화해 JSON gt로 저장.
- `admin_logs/slack/*.jsonl`은 사용자 발화만 있고 확정 코드(gt)가 없어 제외(분할 파일에 사유 기록).
- 논문의 60건(30/30)과 불일치 → 실측 30건을 seed 결정적 **15/15**로 분리하고
  분할 파일과 AS-02에 논문 차이를 기록(수치 날조 금지).

## 누수 방지 메커니즘 (§6 WI-05 핵심)
- `ReplaySplit.holdout_cases(*, consumer)`: consumer가 {"gate","report"}가 아니면
  `ReplayLeakError` 발생. keyword-only라 우회 호출도 차단.
- ga_engine의 적합도 경로는 `search_cases()`만 호출하며, holdout은 탐색 종료 후
  최종 best genome 1개의 보고 평가(`consumer="report"`)에만 사용.
- 단위 테스트로 증명: `holdout_cases(consumer="fitness")` → 예외 (test_wi05_replay.py).
